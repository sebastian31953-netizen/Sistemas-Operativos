Conceptos Clave de Sistemas Operativos

Definiciones formales, modelos analíticos y principios de diseño extraídos directamente de los talleres teóricos y prácticos de las Clases 1, 2 y 3.

Glosario de Conceptos Fundamentales

Principios técnicos necesarios para comprender el funcionamiento y diagnóstico del software de sistema.

SO

Sistema Operativo & Recursos

Software fundamental que actúa como intermediario entre el usuario, las aplicaciones y el hardware físico. Administra y distribuye equitativamente CPU, memoria RAM y almacenamiento como un director de orquesta, evitando que un programa pesado monopolice o congele el computador.

Clase 1Arquitectura
PR

Programa vs Proceso

Un programa es una entidad pasiva y estática almacenada en disco (ej. navegador.exe). Un proceso es una entidad activa y dinámica: un programa cargado en memoria RAM en ejecución al que el sistema operativo le asigna recursos y un espacio de control.

Clase 2Memoria & CPU
PCB

Bloque de Control de Proceso

Estructura de datos en memoria del kernel que almacena el contexto de un proceso: identificador único (PID), estado de ejecución, Contador de Programa (PC), valores de registros de CPU, prioridades de planificación y estado de las operaciones de E/S.

Clase 2Kernel Data
RC

Condición de Carrera (Race Condition)

Fallo de concurrencia donde el resultado final depende del orden impredecible de ejecución de procesos que acceden al mismo dato compartido. Ejemplo del taller: dos transacciones bancarias simultáneas (\$50 y \$20) que provocan pérdida de actualización, dejando el saldo en \$70 en vez de \$120.

Clase 2Concurrencia
SC

Sección Crítica

Región de código donde se manipulan datos o recursos compartidos. El SO debe garantizar las tres condiciones de Dijkstra: 1) Exclusión mutua (máximo un proceso a la vez), 2) Progreso (decisión justa si está libre) y 3) Espera limitada (sin inanición). Ejemplo del taller: reserva simultánea del asiento de cine F5.

Clase 2Exclusión Mutua
SEM

Semáforos (Dijkstra)

Variable entera protegida con dos operaciones atómicas: wait() (reduce valor y bloquea si es ≤ 0) y signal() (aumenta valor y despierta un proceso). Se dividen en semáforos binarios (0 o 1, para exclusión mutua de una impresora) y semáforos contadores (para gestionar un cupo de $N$ conexiones a bases de datos).

Clase 2Sincronización
AMD

Ley de Amdahl y Multinúcleo

Fórmula: Aceleración = 1 / ((1 - P) + P/N). Establece que la aceleración real de un procesador de múltiples núcleos está limitada por la fracción secuencial del software. Además, los hilos de ejecución (Hyper-Threading / SMT) no duplican la potencia física de un núcleo real.

Clase 2Rendimiento
THR

Hiperpaginación (Thrashing)

Fenómeno crítico en el que la memoria RAM está saturada (ej. al 97%) y el sistema traslada masivamente páginas al archivo de paginación en disco. El procesador pasa más tiempo intercambiando datos con el disco que ejecutando instrucciones útiles, provocando congelamientos prolongados.

Clases 1 & 2Memoria Virtual
DST

Sistemas Distribuidos & Transparencia

Arquitectura donde múltiples computadoras autónomas coordinadas por red funcionan como un único sistema. La transparencia oculta al usuario la ubicación física de los servidores, los mecanismos de concurrencia y los fallos de nodos individuales.

Clase 3Redes & Nodos

Cuadros Comparativos de Conceptos

1. Programa vs Proceso (Clase 2)

Característica Programa Proceso
Estado natural Pasivo y estático. Activo y dinámico.
Ubicación Almacenado como archivo ejecutable en disco. Cargado en memoria principal (RAM).
Consumo de recursos Ocupa únicamente espacio de almacenamiento. Consume tiempo de CPU, memoria, descriptores de archivos y periféricos.
Control del sistema El SO lo gestiona como un archivo común. El SO lo controla mediante su Bloque de Control de Proceso (PCB).

2. Interfaz CLI vs Interfaz GUI (Clase 1)

Criterio Línea de Comandos (CLI) Interfaz Gráfica (GUI)
Consumo de recursos Mínimo; ideal para servidores y entornos remotos. Mayor consumo de memoria RAM y aceleración gráfica.
Automatización Alta mediante scripts de shell / PowerShell. Compleja o dependiente de macros.
Curva de aprendizaje Requiere memorizar comandos y sintaxis exacta. Intuitiva y amigable basada en ventanas, iconos y ratón.
Precisión y control Control fino sobre parámetros de ejecución y diagnósticos. Orientada a la interacción directa con el usuario común.

3. Sistema Centralizado vs Sistema Distribuido (Clase 3)

Criterio Sistema Centralizado Sistema Distribuido
Arquitectura de procesamiento Depende exclusivamente de un único servidor principal. Las tareas se distribuyen en múltiples computadores autónomos.
Punto único de falla Sí; la caída del servidor detiene toda la operación comercial. No; posee tolerancia a fallos mediante redundancia de nodos.
Escalabilidad Vertical (ampliar componentes del mismo equipo, con límite físico). Horizontal (incorporar nuevos servidores en clúster sin apagar el sistema).
Complejidad de comunicación Baja; comunicación interna en bus de memoria. Alta; requiere coordinar mensajes, latencias y consistencia en red.

4. Comunicación Síncrona vs Asíncrona (Clase 3)

Modelo Comportamiento del Emisor Caso de Aplicación en la Empresa
Síncrona Envía la solicitud y se bloquea a la espera de la confirmación inmediata. Facturación de caja: el cajero necesita aprobación inmediata del pago antes de entregar la mercancía.
Asíncrona Deposita el mensaje en una cola y continúa trabajando sin esperar. Sincronización de inventario, alertas de stock bajo y reportes gerenciales diarios.
