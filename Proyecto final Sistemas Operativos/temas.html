Clase 1 · Introducción y Fundamentos del SO

Propósito y Abstracción
El sistema operativo actúa como software intermediario que administra el hardware y facilita la interacción del usuario y las aplicaciones: Usuario → Aplicación → SO → Hardware.

Cinco Funciones Críticas
Gestión de procesos (crear, suspender y reanudar tareas), administración de memoria RAM, gestión lógica de archivos en disco, manejo de dispositivos E/S con controladores y provisión de interfaz de usuario.

Administrador de Recursos
Opera como un director de orquesta que distribuye equitativamente CPU, memoria y almacenamiento, priorizando tareas para asegurar la estabilidad del computador.

Clase 2 · Procesos, Concurrencia y Sincronización

Programa vs Proceso
El programa es una entidad pasiva y estática en disco; el proceso es la entidad activa y dinámica en ejecución con memoria RAM y recursos asignados.

PCB y Ciclo de Vida
El Bloque de Control de Proceso guarda PID, estado, contador de programa (PC), registros y prioridades. Ciclo de 5 estados: Nuevo → Listo → Ejecución → Bloqueado → Terminado.

Concurrencia y Sincronización
Condiciones de carrera, sección crítica (criterios de Dijkstra: exclusión mutua, progreso y espera limitada) y semáforos binarios/contadores con operaciones atómicas wait() y signal().

Clase 3 · Sistemas Operativos Distribuidos

Concepto y Transparencia
Conjunto de computadoras independientes coordinadas mediante red percibidas como un único sistema, ocultando al usuario la ubicación física de los recursos.

Arquitectura Cliente-Servidor
Modelo multicapa con balanceador global, servidores de aplicaciones (microservicios), réplicas de datos locales, llamadas RPC y colas asíncronas de mensajes.

Tolerancia y Archivos (DFS)
Redundancia activo-activo con detección por latidos (heartbeats), failover automático en segundos y Sistemas de Archivos Distribuidos con permisos RBAC y bloqueos.

Ciclo de Vida del Proceso: Ejemplo Práctico de Impresión (Clase 2)

Las transiciones de estado descritas en el taller teórico ilustran con precisión cómo opera el planificador del kernel:

1. Nuevo → Listo
El usuario hace clic en “Imprimir”; el sistema operativo crea el proceso, asigna su PCB y lo carga en la memoria RAM en la cola de listos.

2. Listo → Ejecución
El planificador de la CPU le asigna un quantum de tiempo para procesar y estructurar el documento.

3. Ejecución → Bloqueado (Waiting)
El proceso solicita enviar el flujo de datos a la impresora física. Como el periférico de E/S es mecánicamente más lento, el proceso cede voluntariamente la CPU para no desperdiciar ciclos de reloj.

4. Bloqueado → Listo
La impresora termina de recibir los datos y envía una interrupción de hardware al SO. El proceso reingresa a la cola de listos.

5. Listo → Ejecución
El planificador asigna CPU nuevamente para cerrar los descriptores de archivos de trabajo.

6. Ejecución → Terminado
El proceso finaliza su tarea y el sistema operativo libera su memoria RAM y destruye el PCB.
